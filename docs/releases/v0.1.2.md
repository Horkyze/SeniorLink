# SeniorLink 0.1.2 — simpler, verified pairing

Connect the sharing phone and caregiver with **one QR scan**, compare a matching
four-character code, and confirm once. No return scan or code typing is needed.

## Download and update

Download **SeniorLink-0.1.2-debug.apk** from the release assets and install it on
both phones. Android 8.0 or later is required; ARM64, ARMv7 and x86-64 are included.

This APK uses the **same signing certificate as the published 0.1.0 and 0.1.1
APKs**. Install it as an update, without uninstalling. Existing identities, paired
phones and history are retained. Update both phones before starting a new pairing.

This remains a debug-signed family pilot prerelease, not an emergency-response or
medical device. Builds from another machine or CI may have a different signing key.

## Connect a caregiver

1. On the sharing phone, open **Phones → Connect a caregiver**.
2. On the caregiver's phone, open **Phones → Scan QR** and scan once.
3. Compare the four-character code shown on both phones, such as **K7MP**.
4. If the codes match, tap **Codes match — connect** on the sharing phone.

Both phones show **You're connected**. Names are optional. Sharing still starts
only when the sharing phone taps **Start sharing**.

## What changed

- Permanent device signatures and a fresh pairing session bind the verification
  code to the two devices, rather than trusting a displayed name.
- Invitations expire after five minutes. Rejection, cancellation and interrupted
  connections have clear recovery paths; reconnecting keeps the same code.
- Large verification text and vertically arranged buttons work with Android's
  largest font setting. Technical public-key strings are no longer shown in the
  normal phone list.
- Copy/share/paste is available when the caregiver cannot use the camera.
- Pairing uses temporary connections so existing monitoring and catch-up continue.

## Verification

- 23 core and 9 Android unit tests pass.
- The Android 15 ARM64 emulator suite covers real signed pairing, rejection,
  lost replies, revocation, check-in delivery, camera behavior and monitoring.
- Both production pairing controllers pass the full UI flow. Pairing screens and
  actions also pass checks with Android's system font scale set to 2.0.
- APK signatures, native ABI/alignment and checksum-verified archive reconstruction
  are checked before publishing.
- An in-place update from the published 0.1.1 APK preserves settings, identity,
  paired phones and history; a new check-in uses the same permanent identity.

To verify the download, put the APK and `SHA256SUMS` in one directory and run:

```sh
# macOS
shasum -a 256 -c SHA256SUMS
# Linux
sha256sum -c SHA256SUMS
```

Keep both apps open and online while connecting. There are no closed-app push
alerts or guaranteed delivery times. Physical phone-to-phone optical scans and
manufacturer-specific behavior remain on the
[real-phone checklist](https://github.com/Horkyze/SeniorLink/blob/v0.1.2/docs/acceptance.md).
See the [verification record](https://github.com/Horkyze/SeniorLink/blob/v0.1.2/docs/verification.md).
