# SeniorLink 0.1.8 — update links open GitHub release pages

When a newer version is detected, **View release** opens that version's GitHub
release page. Download the APK from **Assets**, then open it to update SeniorLink.
This avoids starting a direct APK download that some browsers block.

The change applies to startup and manual checks in **Settings → App updates**,
including published pilot prereleases. If no browser can open the page, the prompt
provides a copyable release-page link.

## Download and update

Download **SeniorLink-0.1.8-debug.apk** from this release's assets. If your installed
version's direct download is blocked, open this release page manually. After
installing 0.1.8, future update prompts open release pages.

**Install as an update without uninstalling** to preserve identity, pairing,
settings and history. Version 0.1.8 uses the same signing certificate as the
published 0.1.7 APK. Sync protocol 3 is unchanged: 0.1.7 and 0.1.8 can communicate;
paired phones on 0.1.6 or older must also be updated.

This remains a debug-signed family pilot prerelease for Android 8.0 or newer,
including ARM64, ARMv7 and x86-64. Both roles use the same APK.

- All 40 core and 48 Android JVM checks pass; build and lint pass with zero errors.
- All six update-dialog/Settings emulator tests pass, plus three dialog tests at

- Signing compatibility with 0.1.7, native ABI/16 KB alignment and reconstruction

See the [verification record](https://github.com/Horkyze/SeniorLink/blob/v0.1.8/docs/verification.md)

Download `SHA256SUMS` alongside the APK to verify it:

```sh

shasum -a 256 -c SHA256SUMS
# Linux

```
